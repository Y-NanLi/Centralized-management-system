# 部署说明（飞牛 fnOS Docker · Windows）

本文针对**集中管理系统 v1.8.2**，端口固定 `8099`，所有业务数据都在 `data/` 目录。

两种方式，**二选一**，不要同时跑两个实例：

| 方式 | 适用 | 数据位置 | 更新方式 |
| --- | --- | --- | --- |
| Docker（飞牛 / NAS / 服务器） | 长期开机、多人访问 | NAS 上 `./data` | 重建容器、导入新镜像，或 GitHub tag 自动构建 + Watchtower 自动更新 |
| Windows 直接运行 | 当前办公电脑、内网 Windows 服务器 | 项目下 `data/` | 停服务、换代码、再启动 |

> **安全提醒**：本系统是免密码登录，只凭用户名识别身份，管理员用户名固定为 `admin`。**不要直接暴露到公网**。只在局域网、VPN 内使用；如果必须远程访问，请在前面加反向代理并配置 HTTPS 和额外的访问认证。

## 一、Docker 部署（飞牛 fnOS）

### 1. 准备目录

在飞牛文件管理里建目录，例如：

```
/vol1/1000/docker/jizhong
├── Dockerfile
├── docker-compose.yml
├── package.json
├── server.js
├── src/
├── web/
└── data/          # 首次可为空；迁移时放旧系统的 data
```

只上传运行需要的文件，**不要**把 `.git`、临时备份、测试库一起传上去。

`data/` 说明：

```
data/
├── app.db          SQLite 数据库
├── secret.key      登录令牌签名密钥
└── files/          上传的附件（按年-月分目录）
```

### 2. 方式 A：源码本地构建（推荐，支持 SSH 或 Compose 带 build）

在飞牛「Docker → Compose → 新增项目」中：

- 项目名称：`jizhong`
- 项目路径：`/vol1/1000/docker/jizhong`
- 配置方式：选「编辑 / 粘贴」，内容如下

```yaml
services:
  jizhong:
    build: .
    image: jizhong-management:latest
    container_name: jizhong-management
    restart: unless-stopped
    ports:
      - "8099:8099"
    environment:
      TZ: Asia/Shanghai
      APP_SECRET: "换成你自己的固定长随机串"
    volumes:
      - ./data:/app/data
```

如果飞牛界面里的 Compose 不支持 `build`，用 SSH：

```bash
cd /vol1/1000/docker/jizhong
docker compose up -d --build
```

首次构建会拉 `node:22-alpine`，通常 1–3 分钟；本项目零第三方依赖，不需要 `npm install`。

### 3. 方式 B：镜像导入（无 SSH、界面部署）

在装有 Docker Desktop 的电脑上构建：

```powershell
cd D:\dbwork\集中管理系统
docker build -t jizhong-management:latest .
docker save jizhong-management:latest -o jizhong-management-1.8.2.tar
```

把 `jizhong-management-1.8.2.tar` 上传到飞牛，例如 `/vol1/1000/docker/jizhong/`，然后在飞牛 Docker 的镜像页面导入；如果界面没有导入入口，用 SSH：

```bash
docker load -i /vol1/1000/docker/jizhong/jizhong-management-1.8.2.tar
```

> 如果飞牛是 ARM 架构，不要在普通 x86 电脑上直接构建后导入；请在 NAS 上构建，或用 `docker buildx build --platform linux/arm64 --load -t jizhong-management:latest .` 指定架构。

Compose 改成不构建、直接用镜像：

```yaml
services:
  jizhong:
    image: jizhong-management:latest
    container_name: jizhong-management
    restart: unless-stopped
    ports:
      - "8099:8099"
    environment:
      TZ: Asia/Shanghai
      APP_SECRET: "换成你自己的固定长随机串"
    volumes:
      - ./data:/app/data
```

> 本仓库目前只做本地提交，没有配置远程镜像仓库和自动构建，所以**不配置 Watchtower 自动更新**；升级时按下面「更新」手动重建或重新导入镜像。

### 4. 启动与验证

- 项目状态应为「正在运行」，容器名 `jizhong-management`
- 日志中应出现：`集中管理系统已启动：http://localhost:8099`
- 浏览器打开 `http://飞牛IP:8099`
- 用 `admin` 登录，能看到工作台、单据中心、仓库打单、回收站
- 新建一个客户或单据，再重启容器，数据仍在，说明 `./data` 挂载正常

### 5. 更新（重要）

本系统升级会**自动迁移数据库**（v1.8 会自动补仓库流转和回收站字段），但仍然必须先备份：

```bash
cd /vol1/1000/docker/jizhong

# 1. 先停服务，保证数据库一致
docker compose stop

# 2. 备份 data（数据库 + 附件 + 密钥）
tar czf jizhong-data-$(date +%Y%m%d-%H%M).tar.gz data

# 3. 替换代码：server.js、src/、web/、package.json、Dockerfile 等
#    不要覆盖 data/

# 4. 重建并启动
docker compose up -d --build

# 5. 看日志
docker compose logs -f --tail=100
```

验证：管理员能登录、原单据还在、仓库打单页能打开、回收站为空但能打开。若启动失败，恢复 `data` 和旧代码后再排查。

没有 SSH 时：在飞牛项目管理页点「停止」，先把 `data` 下载备份，再替换代码文件，最后点「构建 / 启动」即可。

### 6. 从 Windows 迁到 Docker

1. 在 Windows 上先停止服务，确认 8099 没有进程；
2. 把整个 `D:\dbwork\集中管理系统\data` 复制到飞牛 `/vol1/1000/docker/jizhong/data`；
3. 必须包含 `app.db`、`secret.key`、`files/`；如果服务没停就复制，还要一并复制 `app.db-wal`、`app.db-shm`；
4. 启动容器；
5. 浏览器访问 `http://飞牛IP:8099`，原来的客户、货品、单据、附件都应还在。

> 和旧版单文件工具不同，本系统的数据在服务器 `data/` 里，不依赖浏览器地址。换 IP、换端口不会把数据分成两份。

### 7. Docker 备份与恢复

备份（建议停服）：

```bash
cd /vol1/1000/docker/jizhong
docker compose stop
tar czf jizhong-data-$(date +%Y%m%d).tar.gz data
docker compose start
```

没有 SSH 时：在飞牛项目管理页点「停止」，用文件管理把整个 `data` 打包下载，再点「启动」。

恢复：

```bash
cd /vol1/1000/docker/jizhong
docker compose stop
mv data data.bak
tar xzf jizhong-data-20261128.tar.gz
docker compose start
```

`secret.key` 丢失不会丢业务数据，但所有人需要重新登录；`app.db` 和 `files/` 才是业务数据本体。

### 8. GitHub Tag 自动构建 + 飞牛自动更新（可选）

仓库里已经放好两个文件：

- `.github/workflows/docker-release.yml`：推送 `v*.*.*` 形式的 tag 时，自动构建 `linux/amd64 + linux/arm64` 镜像并推送到 GHCR。
- `docker-compose.ghcr.yml`：飞牛上直接拉 GHCR 的 `latest` 镜像，并带 Watchtower 每 300 秒检查一次更新。

镜像地址：

```text
ghcr.io/y-nanli/centralized-management-system:latest
ghcr.io/y-nanli/centralized-management-system:v1.8.2
```

发布新版本时执行（版本号按实际改）：

```bash
git tag v1.8.3
git push origin v1.8.3
```

推送 tag 后到 GitHub 仓库的 **Actions → Docker Release** 看构建结果。构建成功后，飞牛最多等 5 分钟会自动拉取新 `latest` 并重启容器；`data/` 不参与替换，数据库迁移仍由服务启动时自动完成。

> 普通 `git push` 不会构建镜像，只有推送版本 tag 才触发，避免每次改文档都更新生产。

首次在飞牛启用自动更新：

```bash
cd /vol1/1000/docker/jizhong
# 目录里只需要 docker-compose.ghcr.yml 和 data/，源码可以不传
# 如果已经用旧版 compose 跑过同名容器，先删掉旧容器（data 卷不受影响）
docker rm -f jizhong-management
docker compose -f docker-compose.ghcr.yml pull
docker compose -f docker-compose.ghcr.yml up -d
docker logs -f jizhong-watchtower
```

看到 Watchtower 启动日志后，它只会更新带 `com.centurylinklabs.watchtower.enable=true` 标签的 `jizhong-management`，不会碰 NAS 上的其他容器。

GHCR 包默认可能是私有包。两种处理：

- **改成公开包（推荐，NAS 不用登录）**：GitHub 个人页 → Packages → 找到该镜像 → Package settings → Change visibility → Public。
- **保持私有**：在飞牛执行 `docker login ghcr.io -u Y-NanLi`，输入有 `read:packages` 权限的 PAT；然后取消 `docker-compose.ghcr.yml` 里 `/root/.docker/config.json:/config.json:ro` 这行注释，再重启 Watchtower。

回滚：把 `docker-compose.ghcr.yml` 里的镜像改回上一个**已经构建过**的版本 tag（首个可用版本是 `v1.8.2`，之后每发一个 tag 都会生成对应镜像），例如 `:v1.8.2`，然后：

```bash
docker compose -f docker-compose.ghcr.yml up -d jizhong
```

注意：

- `docker-compose.yml` 是源码本地构建版，`docker-compose.ghcr.yml` 是 GHCR 自动更新版，两者的 `container_name` 相同，**不要同时启动**。
- 国内直连 `ghcr.io` 可能较慢；拉取失败时给 Docker 配代理/镜像加速，或改用阿里云 ACR。
- Watchtower 只负责拉新镜像，不保证业务回滚；发布前仍要先备份 `data/`，并保留旧版本 tag。

## 二、Windows 部署

当前这台生产机就是这种方式：`D:\dbwork\集中管理系统`，端口 `8099`。

### 1. 环境要求

- Windows 10 / 11 / Server
- Node.js **22.13 或更高**（推荐 22.23 LTS；必须使用内置 `node:sqlite` 的 22.x）
- 不需要安装 npm 依赖，不需要 SQLite 客户端，不需要 IIS

检查：

```powershell
node -v
```

应输出 `v22.x`。如果提示「node 不是内部或外部命令」，重装 Node.js 后重新打开终端。

### 2. 放置目录

```text
D:\dbwork\集中管理系统\
├── server.js
├── package.json
├── src\
├── web\
├── data\
│   ├── app.db
│   ├── secret.key
│   └── files\
├── 启动.bat
└── docs\
```

首次部署可以没有 `data`，启动时会自动建库、建目录、写入默认公司主体和管理员账号。

### 3. 启动

双击 `启动.bat`，或在 PowerShell：

```powershell
cd D:\dbwork\集中管理系统
node server.js
```

看到下面内容即成功：

```
集中管理系统已启动：http://localhost:8099
管理员用户名：admin（免密码登录；普通用户可在登录页注册中文用户名）
```

浏览器打开 `http://localhost:8099`，用 `admin` 登录。

关闭命令行窗口即停止服务；`启动.bat` 会先打开浏览器再启动服务。

### 4. 局域网访问

同一局域网内用 `http://这台电脑的IP:8099` 访问。

如果 Windows 防火墙拦截，用管理员 PowerShell 放行端口：

```powershell
New-NetFirewallRule -DisplayName "集中管理系统 8099" -Direction Inbound -Protocol TCP -LocalPort 8099 -Action Allow
```

建议在路由器上给这台电脑固定 IP，避免同事收藏的地址失效。

### 5. 开机自启（可选）

用「任务计划程序」：

1. `Win+R` 输入 `taskschd.msc`；
2. 「创建任务」，名称 `集中管理系统`；
3. 触发器：`登录时` 或 `启动时`；
4. 操作：「启动程序」
   - 程序：`C:\Windows\System32\cmd.exe`
   - 参数：`/c "node server.js >> C:\Temp\jz-8099.out.log 2>&1"`
   - 起始于：`D:\dbwork\集中管理系统`
5. 勾选「不管用户是否登录都要运行」可后台常驻；需要保存登录密码；
6. 保存后手动「运行」一次，浏览器验证 8099。

日志在 `C:\Temp\jz-8099.out.log` 和 `C:\Temp\jz-8099.err.log`。

> 不要用两个任务计划或两个命令行窗口同时启动同一份 `data`，SQLite 会报数据库锁。

### 6. Windows 更新

```powershell
# 1. 只停 8099 上的服务，避免误杀其他 node 进程
$pid = (Get-NetTCPConnection -LocalPort 8099 -State Listen -ErrorAction SilentlyContinue).OwningProcess
if ($pid) { Stop-Process -Id $pid -Force }

# 2. 备份数据
$stamp = Get-Date -Format yyyyMMdd-HHmm
Compress-Archive -Path 'D:\dbwork\集中管理系统\data' -DestinationPath "C:\Temp\jizhong-data-$stamp.zip"

# 3. 替换代码：server.js、src、web、package.json、docs
#    保留 data 目录

# 4. 重新启动
cd D:\dbwork\集中管理系统
node server.js
```

启动时数据库字段会自动迁移。升级后先验证：
- `admin` 能登录
- 原单据、客户、附件数量不变
- 仓库打单页能打开
- 回收站里能看到被删条目，30 天后自动清理

### 7. Windows 备份与恢复

停服务后直接压缩整个 `data`：

```powershell
$pid = (Get-NetTCPConnection -LocalPort 8099 -State Listen -ErrorAction SilentlyContinue).OwningProcess
if ($pid) { Stop-Process -Id $pid -Force }
Compress-Archive -Path 'D:\dbwork\集中管理系统\data' -DestinationPath "D:\backup\jizhong-data-$(Get-Date -Format yyyyMMdd).zip"
```

恢复：

```powershell
$pid = (Get-NetTCPConnection -LocalPort 8099 -State Listen -ErrorAction SilentlyContinue).OwningProcess
if ($pid) { Stop-Process -Id $pid -Force }
Rename-Item 'D:\dbwork\集中管理系统\data' 'data.bak'
Expand-Archive -Path 'D:\backup\jizhong-data-20261128.zip' -DestinationPath 'D:\dbwork\集中管理系统'
cd D:\dbwork\集中管理系统
node server.js
```

如果服务没停就复制数据库，必须同时复制 `app.db`、`app.db-wal`、`app.db-shm` 三个文件。

## 三、配置项

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8099` | 服务端口；Docker 里改端口时，容器内外要对应修改 |
| `HOST` | `0.0.0.0` | 监听地址；只允许本机访问可改 `127.0.0.1` |
| `DATA_DIR` | 项目下 `data/`；Docker 内 `/app/data` | 数据库、密钥、附件目录 |
| `APP_SECRET` | 自动生成到 `data/secret.key` | 令牌签名密钥；多实例或迁移时建议固定 |
| `TZ` | `Asia/Shanghai` | 容器时区 |

固定 `APP_SECRET` 的注意点：

- 不设置时，密钥保存在 `data/secret.key`，只要 `data` 不丢，登录状态就不会因为重启失效；
- 设置了固定值后，以后不要随意更换，否则所有人需要重新登录一次；
- 密钥变化**不影响**客户、单据、附件数据。

上传限制：单文件最大 `100MB`，代码里固定，环境变量改不了。

## 四、常见报错

| 现象 | 原因 / 处理 |
| --- | --- |
| `port is already allocated` / `EADDRINUSE` | 8099 被占用。Docker 可改 `"18099:8099"`，访问改成 18099；Windows 用 `netstat -ano \| findstr 8099` 找占用进程 |
| Docker 构建报 `COPY failed: ... /src not found` | 项目文件没传全；确认 `src/`、`web/`、`server.js`、`package.json` 都在项目目录 |
| 更新后数据没了 | `./data:/app/data` 挂载没配对；先停容器，把旧 `data` 放回项目目录再启动 |
| 登录后马上 401 / 一直被踢 | `APP_SECRET` 被换过，或 `secret.key` 被覆盖；清浏览器 token 后重新登录，或恢复原 `secret.key` |
| 启动报数据库锁 | 同一份 `data` 被两个进程/两个容器同时打开；只保留一个实例 |
| 局域网打不开 | 只监听了 127.0.0.1、防火墙没放行、或访问了错误 IP；检查 `HOST`、防火墙和 `ipconfig` |
| 附件上传失败 | 单文件超过 100MB，或 `data/files` 不可写；检查目录权限和剩余磁盘 |
| 打印空白 / 第二页空白 | 这是浏览器打印设置问题：A4、100%、边距无、关闭页眉页脚；与服务器部署无关 |
| 时间显示不对 | 容器未设置 `TZ=Asia/Shanghai`；Windows 检查系统时区 |
| 忘记管理员密码 | 本系统没有密码，直接用户名 `admin` 登录；账号被停用则改数据库 `users.active=1` |

## 五、上线检查清单

- [ ] 只开放局域网 / VPN，未直接映射到公网
- [ ] `data` 已挂载或位于项目目录，且有备份
- [ ] `admin` 能登录，能看到原有单据
- [ ] 新建客户、单据、上传附件各试一次
- [ ] 送货单能“交仓库”，仓库账号能接收、编辑、打印
- [ ] 删除单据/文件能进回收站，能恢复
- [ ] 服务重启后数据仍在
- [ ] 防火墙、固定 IP、开机自启按需配置
